# CLAUDE.md — grounding for AI assistants

This repository is a turnkey, AI-queryable **genesis ADA database**. Anyone can
clone it and ask an AI where the Cardano genesis ADA went and which stake pools
(SPOs) and DReps it ended up in.

## Where the data is

- **Compact, query-ready database:** `data/abcde_genesis.duckdb` (committed; a
  plain `git clone` gets it instantly, no Git LFS required).
- **Schema you should ground on:** `data/schema_catalog.json` (machine-readable)
  and `docs/SCHEMA.md` (human-readable). Both are regenerated by
  `scripts/build_genesis_db.py` from `anchors.yaml` (→ `seeds` table) and every
  `data/small/*.csv` (one table per file).
- **Full / large dataset:** published via GitHub Releases; pull it with
  `python scripts/fetch_db.py` (lands in `data/release/`, gitignored).

## How to query

- **MCP server (primary):** `mcp_server/server.py` — tools `list_tables()`,
  `describe_table(name)`, `run_sql(sql, max_rows=200)`, `starter_questions()`.
- **CLI fallback:** `python ask.py "your question"` (needs `ANTHROPIC_API_KEY`).

Always call `list_tables()` then `describe_table(name)` to ground your SQL in
the real tables and columns before running `run_sql()`. Do not invent table or
column names.

## Read-only rule (hard constraint)

The database is opened `read_only=True` and every statement is statically
checked. Only a **single** `SELECT` / `WITH` / `PRAGMA` / `EXPLAIN` / `SHOW` /
`DESCRIBE` is permitted. Anything that writes or mutates state
(`INSERT`/`UPDATE`/`DELETE`/`DROP`/`CREATE`/`ALTER`/`ATTACH`/`COPY`/`INSTALL`/
`LOAD`/`EXPORT`/`IMPORT`/`TRUNCATE`/`REPLACE`/`CALL`/`SET`/`RESET`/`VACUUM`) and
multi-statement input is rejected. Never try to work around this.

## Evidence grading standard (`docs/02_GRADING.md`)

Label every claim by what the data proves:

- **FACT** — directly queryable / deterministic from committed or released artifacts.
- **STRONG_INFERENCE** — strongly supported by facts but not uniquely proven.
- **WORKING_HYPOTHESIS** — plausible model with open refutation tests; not a conclusion.
- **UNKNOWN** — not established from current evidence.

When you answer, state the grade and cite the tables you used. Distinguish what
the on-chain flows show from what they do not.

## The hard wording rule

**Never assert off-chain legal ownership, intent, or wallet control beyond what
the on-chain flows and delegations actually show.** Do not write "proved
ownership," "controlled by," "misconduct," or similar off-chain conclusions.
On-chain co-spends, merges, and delegations are evidence of *on-chain linkage*,
not of real-world identity or control. Frame findings as "the trace reaches X"
or "stake descended from seed Y is delegated to pool Z," with the appropriate
evidence grade.
